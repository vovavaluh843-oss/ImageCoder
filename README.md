# Скрытие текста в изображении (RGB-стеганография)

Локальное веб-приложение на **чистых HTML + CSS + JavaScript**. Оно позволяет спрятать
текст внутри PNG-изображения, изменяя значения RGB-каналов пикселей, и достать этот текст
обратно, сравнив исходное и зашифрованное изображения.

Приложение работает **полностью в браузере**: без сервера, без базы данных, без интернета и
без внешних API. Изображения и текст никуда не отправляются.

## Что делает программа

**Вкладка «Шифрование»**

1. Пользователь вводит текст.
2. Пользователь выбирает изображение.
3. Программа показывает размер изображения, доступную ёмкость, размер текста и статус
   («Достаточно места» / «Недостаточно места»).
4. По кнопке «Зашифровать» текст превращается в биты и записывается в каналы R, G, B.
5. Результат показывается как превью и сохраняется кнопкой в файл `encrypted.png`.

**Вкладка «Дешифрование»**

1. Пользователь выбирает исходное изображение и изображение с зашифрованным текстом.
2. Программа проверяет, что оба файла прочитаны и что их размеры совпадают.
3. По кнопке «Расшифровать» каналы сравниваются, биты собираются в байты, байты — в текст UTF-8.
4. Текст показывается в большом поле, есть кнопка «Копировать текст».

### За что отвечает каждый файл

**index.html**

- две панели-экрана (`#panel-encode` и `#panel-decode`), которые переключаются без перезагрузки;
- `<textarea>` для текста, скрытые `<input type="file" accept="image/*">`, зоны перетаскивания,
  превью изображений;
- инфо-панель: размер изображения, доступная ёмкость, размер текста, статус;
- блоки сообщений об ошибках (`#msg-encode`, `#msg-decode`) и блок результата дешифрования.

**style.css**

- CSS-переменные с цветами, общая тёмная тема;
- карточки, вкладки-«пилюли», кнопки (основная/вторичная), поля ввода;
- зоны загрузки с пунктирной рамкой и подсветкой при перетаскивании файла;
- цвета статусов (зелёный/жёлтый/красный) и цветовые варианты сообщений об ошибках;
- адаптивная сетка `grid` и подстройка под узкие экраны.

**script.js**

Разделён на две части.

1. **Чистая логика алгоритма** — функции, которые работают только с числами и массивами
   (`textToBytes`, `bytesToBits`, `buildBitStream`, `encodeBitIntoChannel`, `decodeMessage` и т. д.).
   Их можно перенести в Node.js или другой проект без изменений.
2. **Работа с браузером** — чтение файлов через `FileReader`, отрисовка на `<canvas>`,
   `getImageData` / `putImageData`, сохранение PNG, переключение вкладок, вывод ошибок.

## Как запустить

**Способ 1 (самый простой).** Дважды кликнуть по `index.html` — файл откроется в браузере.

**Способ 2 (через локальный сервер).** Некоторые браузеры строже относятся к файлам,
открытым напрямую, поэтому можно поднять простейший сервер:

```bash
cd путь/до/проекта
python3 -m http.server 8000
```

и открыть в браузере <http://localhost:8000>.

Никаких `npm install`, сборки и зависимостей не требуется.

## Как пользоваться

### Спрятать текст

1. Откройте вкладку **«Шифрование»**.
2. Введите текст в большое поле (поддерживаются русский, английский, цифры, спецсимволы, emoji).
3. Нажмите **«Выбрать изображение»** или перетащите файл прямо в пунктирную зону.
   Возникает превью, а ниже — размер, ёмкость, размер текста и статус.
4. Если статус зелёный, нажмите **«Зашифровать»**.
5. Нажмите **«Сохранить изображение (encrypted.png)»** — в загрузки уйдёт файл `encrypted.png`.

### Достать текст

1. Откройте вкладку **«Дешифрование»**.
2. Загрузите **исходное** изображение (то самое, до шифрования) и **зашифрованное**
   (`encrypted.png`). Превью показывается для обоих.
3. Проверьте строку «Проверка изображений» — размеры должны совпадать.
4. Нажмите **«Расшифровать»**.
5. Текст появится в поле «Результат дешифрования», кнопка **«Копировать текст»** скопирует его.

> Важно: `encrypted.png` нельзя пересохранять в JPEG, обрезать, масштабировать и делать
> скриншоты — иначе значения каналов изменятся и текст не прочитается.

## Как работает алгоритм

Общая схема:

```
ШИФРОВАНИЕ
  ТЕКСТ → UTF-8 → БАЙТЫ → БИТЫ 0/1
     [32 бита длины сообщения][биты текста]
        ↓
  бит 0 → значение RGB-канала НЕ ИЗМЕНЯЕМ
  бит 1 → значение RGB-канала ИЗМЕНЯЕМ НА 1
        ↓
  НОВОЕ PNG-ИЗОБРАЕНИЕ (encrypted.png)

ДЕШИФРОВАНИЕ
  ИСХОДНОЕ ИЗОБРАЖЕНИЕ + ЗАШИФРОВАННОЕ ИЗОБРАЖЕНИЕ
        ↓  сравнение соответствующих каналов R, G, B
  значения равны      → бит 0
  значения различаются → бит 1
        ↓
  БИТЫ → БАЙТЫ → UTF-8 → ИСХОДНЫЙ ТЕКСТ
```

### Шаг 1. Текст → UTF-8 → байты

Используется стандартный `TextEncoder`:

```js
new TextEncoder().encode("Привет");
// Uint8Array [208, 158, 209, 128, 208, 184, 208, 178, 208, 181, 209, 130]
// то есть D0 9F D1 80 D0 B8 D0 B2 D0 B5 D1 82 — 12 байт
```

Каждая кириллическая буква в UTF-8 занимает 2 байта, латинская — 1 байт,
emoji — обычно 4 байта. Именно поэтому размер текста в интерфейсе показывается **в байтах**,
а не в символах.

### Шаг 2. Байты → биты

Каждый байт расширяется в 8 битов, **старший бит идёт первым**:

```js
// байт 208 = 0xD0 = 11010000
bytesToBits([208]); // [1, 1, 0, 1, 0, 0, 0, 0]
```

Обратно биты собираются в байты функцией `bitsToBytes` (побитово: `byte = (byte << 1) | bit`).

### Шаг 3. 32-битный заголовок с длиной

Изображение — это «плоский» поток битов, и конец сообщения по самому тексту определить нельзя.
Поэтому перед текстом записывается **заголовок фиксированного размера — 32 бита**, в котором
лежит количество **байт** текста:

```
[ 32 бита: длина N ][ N × 8 бит самого текста ]
```

Пример: для текста `Привет` (12 байт) первые 32 бита будут `000...00001100`,
а дальше пойдут 96 битов самого текста. При дешифровании сначала читаются эти 32 бита,
превращаются в число, и уже по нему понятно, сколько битов читать дальше.

Всё это делает функция `buildBitStream(text)`.

### Шаг 4. Как бит 0 и бит 1 записываются в изображение

Один RGB-канал хранит один бит.

| Бит | Что делаем с каналом              | Пример      |
| --- | --------------------------------- | ----------- |
| `0` | значение канала не меняем         | `120 → 120` |
| `1` | значение канала меняем ровно на 1 | `120 → 121` |

Детерминированная стратегия для бита `1` (чтобы код был предсказуемым):

```
если значение < 255 → увеличить на 1
если значение == 255 → уменьшить на 1
```

То есть:

```
0   → 1
1   → 2
120 → 121
254 → 255
255 → 254
```

Код функции:

```js
function encodeBitIntoChannel(value, bit) {
  if (bit === 0) return value; // 120 -> 120
  if (value === 255) return 254; // 255 -> 254 (256 получить нельзя)
  return value + 1; // 0 -> 1, 120 -> 121, 254 -> 255
}
```

### Шаг 5. Обработка значений 0 и 255

Диапазон канала — от 0 до 255, выйти за него нельзя (`Uint8ClampedArray` всё равно бы обрезал
значение, но лучше делать это явно):

- нужно записать `1`, канал равен `0` → получаем `1` (увеличение);
- нужно записать `1`, канал равен `255` → получаем `254` (уменьшение);
- любое значение между ними → увеличиваем на 1.

Важно, что направление изменения при чтении **не анализируется**: бит извлекается только из
факта «значение изменилось / не изменилось». Поэтому `255 → 254` и `120 → 121` читаются
абсолютно одинаково — как `1`.

### Шаг 6. Порядок обхода пикселей

В `ImageData.data` пиксели лежат так: `R G B A R G B A R G B A ...`. Альфа-канал (`A`)
не используется и никогда не меняется.

```
Пиксель 1: R G B | A     ← сюда идут биты №0, №1, №2
Пиксель 2: R G B | A     ← биты №3, №4, №5
Пиксель 3: R G B | A     ← биты №6, №7, №8
...
```

Индекс в массиве для номера канала считается так:

```js
pixel = Math.floor(channelNumber / 3);
component = channelNumber % 3; // 0 = R, 1 = G, 2 = B
index = pixel * 4 + component; // +3 был бы альфа-канал
```

Пример: если первые три бита сообщения `1 0 1`, то у первого пикселя R изменится на 1,
G останется как есть, B изменится на 1.

### Шаг 7. Сохранение результата

Изменённые пиксели кладутся на `<canvas>` через `putImageData()`, затем
`canvas.toDataURL("image/png")` даёт PNG, который скачивается как `encrypted.png`
с помощью временной ссылки `<a download="encrypted.png">`.

## Как выполняется дешифрование

Для дешифрования нужны **два изображения одинакового размера**: исходное и зашифрованное.

Пиксель за пикселем, канал за каналом сравниваются значения:

```js
encrypted === original  → 0
encrypted !== original  → 1
```

Примеры:

```
Исходное 120, зашифрованное 120  → равны      → бит 0
Исходное 120, зашифрованное 121  → различаются → бит 1
Исходное 255, зашифрованное 254  → различаются → бит 1
```

Дальше:

1. первые 32 бита превращаются в число — это длина текста в байтах;
2. читается `длина × 8` следующих битов;
3. биты собираются в байты;
4. байты передаются в `new TextDecoder("utf-8", { fatal: true })` — получается исходный текст.

`fatal: true` нужен затем, чтобы испорченные данные не превратились в «кракозябры»:
декодер выбросит ошибку, и приложение честно скажет, что расшифровать сообщение не удалось.

## Зачем нужно исходное изображение

Этот алгоритм хранит информацию **не в значении канала, а в факте его изменения**.
Само по себе значение `121` ничего не значит: оно может быть и «изменённым», и исходным.
Поэтому, чтобы понять, какой канал менялся, нужен «эталон» — оригинальное изображение
до записи. Отсюда следует важное:

- исходное изображение нужно **сохранить** до шифрования;
- для дешифрования подходит только тот же самый файл, а не «почти такой же»;
- если исходного изображения нет, достать текст этим способом нельзя.

## Как рассчитывается вместимость

```
всего битов        = ширина × высота × 3
максимум байт текста = floor((ширина × высота × 3 − 32) / 8)
```

За 32 бита заголовка мы «платим» всегда.

| Размер изображения | Всего битов | Максимум текста         |
| ------------------ | ----------- | ----------------------- |
| 20 × 10            | 600         | 71 байт                 |
| 100 × 100          | 30 000      | 3 746 байт              |
| 1920 × 1080        | 6 220 800   | 777 596 байт (≈ 759 КБ) |

Приложение считает это автоматически и показывает в строке «Доступная ёмкость», а перед
шифрованием сравнивает с размером сообщения. Если текст больше — шифрование не запускается,
и показывается ошибка с объяснением причины.

Обратите внимание: размер текста считается **в байтах UTF-8**. Русская буква — 2 байта,
emoji — 4 байта, поэтому «300 символов» кириллицы — это 600 байт.

## Почему используется PNG, а не JPEG

- **PNG** сжимается без потерь: байты пикселей сохраняются ровно такими, какими были записаны.
  Значит, `121` останется `121`, и сравнение с оригиналом сработает.
- **JPEG** использует сжатие с потерями (дискретное косвенное преобразование, квантование,
  chroma subsampling). После сохранения в JPEG значения каналов меняются даже у «невидимого»
  глазом изображения — меняются не только те каналы, которые правили мы, но и соседние.
  В результате сравнение «равен/не равен» даёт случайные биты, и текст не читается.

Поэтому результат всегда сохраняется через `canvas.toDataURL("image/png")`, а в интерфейсе
есть напоминание не пересохранять файл в JPEG.

## Ограничения алгоритма

1. **Нужно исходное изображение.** Без оригинала извлечь текст невозможно (см. выше).
2. **Это стеганография, а не шифрование.** Текст не защищён паролем и не превращается в «кашу»:
   кто получит оба изображения — восстановит сообщение за секунды.
3. **Нет защиты от изменений.** Обрезка, масштабирование, поворот, повторное сохранение,
   пересылка в мессенджере со сжатием, скриншот — всё это меняет пиксели и разрушает сообщение.
4. **Прозрачность мешает.** Полупрозрачные пиксели браузер при отрисовке на canvas пересчитывает
   (premultiplied alpha), их RGB может измениться. Приложение предупреждает, если в файле есть
   пиксели с `A < 255`.
5. **Единственный признак присутствия данных** — статистика: после записи примерно половина
   каналов отличается от оригинала на 1, и при наличии оригинала такие пиксели легко найти.
6. **Нет контрольной суммы.** Ошибка в одном бите меняет один символ или делает UTF-8
   некорректным; приложение заметит это через `fatal: true`, но исправить не сможет.
   (При желании можно добавить CRC32 в заголовок.)
7. **Ограниченная вместимость**: см. формулу выше.
8. **Большие изображения требуют памяти**: `ImageData` хранит 4 байта на пиксель,
   поэтому фото 10000 × 10000 пикселей может не поместиться в память вкладки.

## Сообщения об ошибках

Все ошибки показываются прямо в интерфейсе, под кнопкой.

| Сообщение                                                                   | Причина и что делать                                                                                   |
| --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| «Текст не введён»                                                           | Пустое поле текста — введите сообщение.                                                                |
| «Изображение не выбрано»                                                    | Сначала загрузите изображение.                                                                         |
| «Текст слишком большой»                                                     | Сообщению нужно больше битов, чем есть в изображении. Возьмите изображение больше или сократите текст. |
| «Файл не является изображением»                                             | Выбран не графический файл.                                                                            |
| «Не удалось прочитать файл»                                                 | Файл занят другой программой, повреждён или к нему нет доступа.                                        |
| «Изображение повреждено»                                                    | Браузер не смог декодировать картинку.                                                                 |
| «Исходное и зашифрованное изображения должны иметь одинаковый размер»       | Подображена не пара. Нужны оригинал и полученный `encrypted.png` одного размера.                       |
| «Размеры Canvas не совпадают»                                               | Внутренняя проверка: пиксельные массивы разной длины.                                                  |
| «Заголовок содержит некорректную длину (0 байт)»                            | Изображения идентичны во всех каналах — скрытого текста в них нет.                                     |
| «Заголовок заявляет N байт, но...»                                          | Данные повреждены или изображения не являются парой.                                                   |
| «Сообщение невозможно расшифровать... не является корректным текстом UTF-8» | Байты читаются как мусор: не тот оригинал, файл пересохранён в JPEG или изменён.                       |
| «Не удалось прочитать пиксели (Canvas защищён)»                             | Браузер запретил чтение пикселей (обычно из-за изображений с других доменов).                          |
| «Браузер не разрешил копирование»                                           | Не удалось использовать буфер обмена — текст выделен, нажмите Ctrl+C.                                  |

## Карта функций в script.js

### Чистая логика (без браузера)

| Функция                            | Что делает                                                        |
| ---------------------------------- | ----------------------------------------------------------------- |
| `textToBytes(text)`                | Текст → байты UTF-8 (`TextEncoder`).                              |
| `bytesToText(bytes)`               | Байты UTF-8 → текст (`TextDecoder`, `fatal: true`).               |
| `bytesToBits(bytes)`               | Байты → поток битов (старший бит первым).                         |
| `bitsToBytes(bits, offset)`        | Поток битов → байты, первые `offset` битов пропускаются.          |
| `lengthToHeaderBits(n)`            | Число (длина в байтах) → 32 бита заголовка.                       |
| `headerBitsToLength(bits)`         | 32 бита заголовка → число.                                        |
| `buildBitStream(text)`             | Готовит `[32 бита длины][биты текста]`.                           |
| `calculateCapacity(w, h)`          | Вместимость: всего битов и максимум байт текста.                  |
| `channelToDataIndex(n)`            | Номер RGB-канала → индекс в `ImageData.data` (с пропуском альфы). |
| `encodeBitIntoChannel(value, bit)` | Запись одного бита в одно значение канала.                        |
| `decodeBitFromChannels(a, b)`      | Чтение одного бита из пары значений.                              |
| `encodeMessage(data, w, h, bits)`  | Записывает весь поток битов в копию пиксельного массива.          |
| `readBits(orig, enc, count)`       | Считывает `count` битов сравнением двух изображений.              |
| `decodeMessage(orig, enc)`         | Два `ImageData.data` → исходный текст (со всеми проверками).      |

### Работа с браузером

| Функция                                     | Что делает                                                                |
| ------------------------------------------- | ------------------------------------------------------------------------- |
| `loadImage(file)`                           | Читает файл через `FileReader` в data URL и загружает в `<img>`.          |
| `extractImageData(image)`                   | Рисует изображение на `<canvas>` и возвращает `getImageData()`.           |
| `countTransparentPixels(imageData)`         | Считает пиксели с `A < 255` (для предупреждения).                         |
| `warnAboutTransparency(...)`                | Показывает предупреждение о прозрачности.                                 |
| `showPreview` / `clearPreview`              | Показывает и убирает превью в зоне загрузки.                              |
| `setupDropzone(zone, input, onFile)`        | Привязывает кнопку и перетаскивание файла к одному `<input type="file">`. |
| `updateEncodeInfo` / `updateDecodeInfo`     | Пересчитывают ёмкость, размер текста и статусы.                           |
| `onEncodeClick`                             | Полный цикл шифрования и создание PNG.                                    |
| `onSaveClick`                               | Скачивание `encrypted.png`.                                               |
| `onDecodeClick`                             | Проверки пары изображений и дешифрование.                                 |
| `onCopyClick`                               | Копирование результата в буфер обмена (с запасным способом).              |
| `showMessage` / `hideMessage` / `setStatus` | Вывод сообщений и цветных статусов.                                       |
| `activateTab` / `init`                      | Переключение вкладок и подключение обработчиков.                          |
